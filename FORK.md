# Fork features

What this fork (`drKreshel/t3code`) adds to upstream `pingdotgg/t3code`, where each feature touches upstream files, and where its data lives. Upstream updates read this to spot overlap and conflicts; see the update policy in [`update-editor`](.agents/skills/update-editor/SKILL.md).

Fork code lives in new files: `apps/server/src/fork/**`, `packages/provider-core/src/server/fork/**`, `packages/contracts/src/fork*.ts`, `apps/web/src/components/{boards,skills,agentContext,threadPins}`, `apps/web/src/state/{boards,workspaces,skills,agentContext,threadPins}.ts`, and `scripts/fork/`. Upstream files only get thin hooks, usually marked `Fork:`. Every fork feature also registers in the shared hooks below, so they are not repeated per feature.

**Shared hooks:** `packages/contracts/src/{rpc,index}.ts` (RPC group and exports), `apps/server/src/auth/RpcAuthorization.ts` (scope per method), `apps/server/src/observability/RpcInstrumentation.ts` (trace aggregate per method), `packages/client-runtime/src/rpc/client.ts` (stream methods), `apps/server/src/ws.ts` (`makeForkRpcHandlers`), `apps/server/src/server.ts` (service layers), `apps/server/src/mcp/McpHttpServer.ts` (fork toolkits via `toolkitRegistration`; their handlers declare caller access with `McpToolAccess`), `packages/provider-core/src/server/runtimeInstructions.ts` (appends `fork/runtimeInstructions.ts`), `apps/server/src/provider/{AgentContextBudget.test.ts,agentContextBudget.json}` (mocks for fork tool services; the budget records the fork's own context size, so raise it when a fork feature adds tools or instructions).

## Fixes upstream could take

Small fixes to upstream behavior. When upstream fixes the same thing, take upstream's version and drop ours.

- Codex native subagents keep the model and reasoning effort reported by newer `SubAgentActivity` notifications: `effect-codex-app-server/_internal/shared.ts`, `orchestration-v2/Adapters/CodexAdapterV2.ts`.
- Agents can permanently delete chats through `t3_thread_organize`: `mcp/toolkits/thread/{tools,handlers}.ts`.
- `list_scheduled_tasks` says `lastRunStatus` reports dispatch, not the agent turn: `contracts/orchestratorMcp.ts`.
- An accepted automatic tick of a chat-bound scheduled task cancels that task's older ticks still waiting in the chat's queue (held or not), so a stale prompt never runs late; Run now, webhook deliveries, user messages, other tasks, running work and holds are untouched: `fork/scheduledTasks/tickSupersession.ts`, hooked in `scheduledTasks/ScheduledTaskService.ts` (dispatch ids and one call after dispatch), test in `orchestration-v2/runtimeLayer.test.ts`.
- Scrolling up while a turn streams no longer snaps the chat back to the bottom (upstream #20366): LegendList's queued end-pin frame now skips when the user scrolled toward the start since it was queued or the app turned `maintainScrollAtEnd` off. Web bundles only (`react.js`, `react.mjs`) in `patches/@legendapp__list@3.3.5.patch`, test in `scripts/legend-list-maintain-at-end.test.ts`.
- A chat scrolled up into history no longer jumps to the bottom when rows change under it (rows re-keyed and laid out from estimated sizes, rows removed): only scrolling toward the end turns live-follow back on, not content bringing the end into view. `apps/web/src/components/chat/useTimelineFollow.ts` (`onIsAtEndChange`), test in `useTimelineFollow.browser.test.tsx`.
- A chat whose worktree was removed outside T3 and that upstream does not recreate (a path outside the managed worktrees folder, such as a removed ticket workspace, or no branch) continues in the project checkout instead of failing every send; upstream recreates managed worktrees and reports when that fails: `orchestration-v2/ProviderTurnStartService.ts`, test in `ProviderTurnStartService.test.ts`.
- Answers to "Input needed" questions show as the user's reply in the chat and search: message-mode `async-answer:` messages are no longer folded into the question card, and live answers (Claude AskUserQuestion) get a client-only reply bubble: `client-runtime/work-log/userInput.ts` (`liveQuestionReplyText`), web `session-logic.ts`, mobile `lib/threadActivity.ts`, server `orchestration-v2/ThreadFind.ts` and `ThreadSearch.ts` (keeps `async-answer:` messages in Cmd+K message search).
- A new chat shows its messages again: the Stop banner (upstream #27252) read the thread detail for an unsent draft, the server answered not found, and the client parked that thread as deleted for good. It now reads only once the server thread exists: `apps/web/src/components/chat/useThreadLifecycle.tsx`.
- `t3_thread_search` takes `allProjects` to search every project when an agent does not know a thread's project: `mcp/toolkits/thread/{tools,handlers}.ts`.
- User docs additions: `docs/user/composer.md`, `docs/user/thread-sidebar.md`.
- A preview operation the server browser times out itself reports its own reason (such as a snapshot of a page too busy to capture) instead of the broker's unexpired 15s budget; Playwright's generic "Timeout Nms exceeded" keeps upstream's message: `mcp/PreviewAutomationBroker.ts`, `contracts/previewAutomation.ts`.
- Agent browser actions in a desktop preview tab (clicks, typing that calls focus()) hand keyboard focus back to the composer when they end, layered on upstream's focus emulation in the desktop relay: `preview/DesktopBrowserHost.ts` (`trackFocus` around `holdFocus`), `desktop/src/{preload.ts,ipc/channels.ts,ipc/methods/preview.ts}`, `contracts/ipc.ts`, `browser/{ElectronBrowserHost.tsx,previewHostFocus.ts}`.
- WhatsApp Web receives a plain Chrome UA and client hints per preview tab without changing the persistent browser session or other sites: `packages/shared/src/preview.ts`, `packages/contracts/src/ipc.ts`, `apps/desktop/src/{ipc/methods/preview.ts,preview/Manager.ts}`, `apps/web/src/browser/HostedBrowserWebview.tsx`.

## Data

- `<state dir>/fork.sqlite`: boards, tickets, workspaces, templates, settings, chat pins. Migrations in `apps/server/src/fork/ForkDatabase.ts` are append-only; never edit a shipped one.
- The dropped sidebar folders feature left `fork_tickets.folder`, `fork_task_folders`, and `fork_chat_folders` in `fork.sqlite`. Nothing reads them; they stay because migrations are append-only.
- `request_human` blockers ride inside upstream's runtime request payload in `state.sqlite`.

Keep this file current: add a row when a fork feature lands, update its touch points when a merge moves them, and remove the row when the fork drops the feature in favor of upstream's.
